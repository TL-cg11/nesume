## 1. 결과 요약

계정 삭제(B20) 뒤 **"잔존 0건"**을 확인합니다(spec 10.2, tasks B23).

| 확인 대상 | 기준 |
|---|---|
| DB | 사용자 ID가 들어가는 **모든 테이블·컬럼을 자동으로 찾아** 0건(users FK, `owner_id`·`user_id`·`owner_user_id`·`shared_with`, JSON 공유 목록 안의 `user_id`). 다른 팀이 테이블을 추가해도 자동 포함 |
| 감사 로그 | 원래 ID로 된 행 0건(익명 ID로 치환·보존) |
| 데이터 키 | `user_keys` 0건 → 백업의 대응표도 복호화 불가 |
| 파일 | S3 `users/{id}/` 0건 |
| 로그인 계정 | Cognito에 없음 |

- 의도된 예외: `templates.created_by`(운영자 작성 이력 보존, B1 설계)

## 2. 실행

```
python -m app.features.deletion.verify --user-id <id> [--user-id ...]   # 지정 계정 검사
python -m app.features.deletion.verify --e2e                             # 임시 계정: 채우기 → 30일 경과 처리 → 삭제 → 검사
```
- 하나라도 남으면 종료 코드 1
- `--e2e`는 임시 계정에 자소서·버전(개인정보 포함)·경험·임베딩·공유(작성자·멘토 양방향)·코멘트·감사 로그·S3 파일·다운로드 토큰을 만들고, **그 계정만** 삭제한 뒤 검사합니다. 다른 사용자 데이터가 같이 지워지면 실패
