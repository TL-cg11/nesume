# [B10] 멘토 공유 API — 완료

- 담당: B (자소서 관리·문서)
- 완료일: 2026-10-23
- 상태: 구현 완료, **D 라우터 등록 요청**, C 벡터 동기화는 병합 후 연결
- 마이그레이션: `0012` (`shares.version_ids`)

---

## 1. 결과 요약

자소서 작성자가 멘토에게 자소서를 **기간을 정해 읽기 전용으로** 공유합니다(spec 3.7).

| 규칙 | 내용 |
|---|---|
| 공유 기간 | 사용자가 종료일을 고름. 기본은 공유일 포함 7일째 날, 최대 공유일 포함 30일째 날 |
| 만료 시각 | 종료일 다음 날 00:00 (한국 시간). 저장은 UTC |
| 연장 | 유효한 공유만. 연장일 포함 30일째 날까지, 현재 종료일보다 뒤 |
| 공유 내용 | **공유 시점의 문항별 최신 버전 고정**. 이후 수정본은 멘토에게 보이지 않음 |
| 개인정보 | 멘토에게는 토큰 상태(`[[PHONE_1]]`) 그대로. 원문 복원은 작성자 본인만(B7) |
| 취소 | 만료와 같게 취급. 끝난 공유는 되살리지 않고 다시 공유하면 새로 생성 |
| 같은 멘토에게 다시 공유 | 유효한 공유가 있으면 확인 문구 → 확인 후 생성 (아래 표) |
| 멘토 지정 | 멘토 사용자 ID. 멘토 열람 API는 로그인 토큰 역할이 `mentor`여야 함 |

**같은 멘토에게 유효한 공유가 있을 때**

| 경우 | 확인 문구 | 확인 후 |
|---|---|---|
| 같은 자소서, 같은 내용 | "이 멘토에게 같은 내용의 자소서가 이미 공유되어 있습니다(종료일까지). 기존 공유를 종료하고 새로 공유할까요?" | 기존 공유 종료 + 새로 생성 |
| 같은 자소서, 그 뒤 수정함 | "이 멘토에게 이 자소서의 이전 버전이 공유되어 있습니다(종료일까지). 기존 공유를 종료하고 현재 버전으로 새로 공유할까요?" | 기존 공유 종료 + 새로 생성 |
| 다른 자소서 | "이 멘토에게 다른 자소서가 공유되어 있습니다. 기존 공유와 별개로 이 자소서를 공유할까요?" | 기존 공유 유지 + 새로 생성 |

## 2. API

| 대상 | 기능 | 주소 |
|---|---|---|
| 작성자 | 공유 생성 | `POST /resumes/{id}/shares` `{mentor_id, end_date?, confirm?}` |
| 작성자 | 공유 목록(상태 포함) | `GET /resumes/{id}/shares` |
| 작성자 | 연장 | `POST /shares/{share_id}/extend` `{end_date}` |
| 작성자 | 취소 | `DELETE /shares/{share_id}` |
| 멘토 | 받은 공유 목록(유효한 것만) | `GET /mentor/shares` |
| 멘토 | 공유된 자소서 열람 | `GET /mentor/shares/{share_id}` |

- 확인이 필요하면 409, `code: "share_confirm_required"`, `errors: {kind: same_content / older_version / other_resume}`, `detail`에 문구. 화면은 문구를 보여주고 `confirm: true`로 다시 요청
- 다른 사람의 자소서·공유, 끝난 공유, 삭제된 자소서 → 404. 멘토 API를 멘토가 아닌 역할로 호출 → 403
- 공유 뒤 삭제된 문항은 멘토 화면에서 빠짐

## 3. 동기화

- 원본은 `shares`. 생성·연장·취소마다 같은 트랜잭션에서 `resumes.shared_with`를 갱신: `[{user_id, expires_at: "2026-10-29T15:00:00Z"}]`(유효한 공유만, `Z` 명시)
- 벡터 메타데이터: C `sync_shared_with` 호출 지점(`features/share/index_hooks.py`). C 브랜치 병합 후 연결
- 만료는 시간이 지나 자동으로 되므로 복제본에 남아 있어도 C6가 `expires_at > now()`로 거름
