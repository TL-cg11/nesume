## 1. 결과 요약

- 자소서·문항 생성/조회/수정/삭제, 문항별 버전 저장·타임라인·비교·복원 API
- 자소서 목록, 문항 편집기, 버전 기록, 버전 비교 화면
- 본인 자소서만 접근 가능, 다른 사용자의 자소서는 "없음(404)"으로 응답

## 2. 주요 규칙 (spec 3.1)

- 저장할 때마다 새 버전 생성, 덮어쓰기 없음
- 이전 버전 복원 = 그 내용으로 새 버전 생성 (기록에 "vN에서 복원" 표시)
- 문항당 버전 50개 초과 시: 저장은 되고 "50개 초과" 안내만 표시. 압축 방식은 팀 확인 후 구현
- 자소서·문항 삭제는 소프트 삭제(목록에서 사라짐), 30일 후 완전 삭제(B20)
- 등급·소유자·생성 방식(source)은 요청으로 지정할 수 없음. 서버가 부여

## 3. API

| 동작 | 경로 |
|---|---|
| 자소서 목록·생성 | `GET/POST /resumes` |
| 자소서 상세(문항 + 최신 버전)·수정·삭제 | `GET/PATCH/DELETE /resumes/{id}` |
| 문항 추가 | `POST /resumes/{id}/questions` |
| 문항 수정·삭제 | `PATCH/DELETE /resumes/{id}/questions/{qid}` |
| 버전 저장(수동)·타임라인 | `POST/GET .../questions/{qid}/versions` |
| 버전 단건 | `GET .../versions/{vid}` |
| 두 버전 비교 | `GET .../versions/diff?from=1&to=2` |
| 복원 | `POST .../versions/{vid}/restore` |

## 4. 다른 팀이 알아야 할 것

**A (작성 AI)**
- 리라이팅 후보 선택 시 새 버전 저장은 함수 호출: `app.features.resumes.service.create_version(db, owner_id, resume_id, question_id, body, source="ai")`
- 본문 저장 경로에 PII 처리 지점(`app/features/resumes/pii_hooks.py`)이 있음 → **10/22 A1 + B7 연결 완료**: 본문은 토큰화 상태로 저장, 주민번호·계좌번호는 저장 거부(422). 상세는 B7.md

**C (공고·추천)**
- 임베딩은 30일 후 완전 삭제 때 지움. 그 전(소프트 삭제 기간)에는 **검색 필터에서 `deleted_at IS NULL` 조건으로 제외 필요** (C6)

**D (인프라·인증)**
- `app/app/db.py`에 요청 단위 DB 세션 `get_db()` 추가, `app/app/main.py`에 라우터 등록 한 줄 추가 (D 소유 파일, 리뷰 요청)
- 화면 확인용으로 **개발 서버 전용 토큰 입력란**을 둠 (`web/src/app/dev/DevTokenPanel.jsx`). 운영 빌드에는 포함되지 않음. D7 로그인 화면 추합 시 삭제
- 사용자의 첫 요청 시 `users` 행을 자동 생성함(토큰의 sub 기준)
