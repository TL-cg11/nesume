## 1. 결과 요약

- 문서 테이블 7개에 보안 등급 `grade` 컬럼 추가
- 등급 값은 DB에서 5종으로 제한, 테이블별 기본 등급은 spec 6.4를 따름
- tasks B2의 shared_with·expires_at은 `resumes.shared_with`에 멘토별 만료와 함께 저장

## 2. 등급 값

`public` / `internal` / `personal` / `sensitive` / `confidential` (공개 / 내부 / 개인 / 민감 / 기밀)

- 코드에서는 `app.models._common.Grade` enum 사용
- 벡터 메타데이터에도 같은 값을 사용 (C3)
- 명칭은 D1 확정 시 맞춤

## 3. 테이블별 기본 등급 (spec 6.4)

| 등급 | 테이블 |
|---|---|
| personal | resumes, questions, versions, experiences, applications |
| internal | templates |
| sensitive | audit_logs |

- 저장 시 등급을 따로 지정하지 않아도 기본 등급이 자동으로 붙음 (ORM, SQL 직접 INSERT 모두)
- 정의되지 않은 값(예: `secret`)은 DB가 거부
- 클라이언트 입력으로 등급을 바꾸지 못하게 막는 것은 B8(3단계)

## 4. 공유 컬럼 (shared_with·expires_at)

공유 대상은 자소서뿐(spec 3.7)이고 멘토마다 만료일이 다를 수 있어, 한 컬럼에 함께 저장함.

```json
resumes.shared_with = [
  {"user_id": "<멘토 sub>", "expires_at": "2026-10-22T00:00:00+00:00"},
  {"user_id": "<멘토 sub>", "expires_at": "2026-11-14T00:00:00+00:00"}
]
```

- 기본값 `[]`, 배열이 아니면 DB가 거부
- 공유 이력의 원본은 `shares` 테이블. 생성·만료·취소 시 B10(멘토 공유 API)에서 `resumes.shared_with`와 벡터 메타데이터를 함께 갱신

## 5. 다른 팀이 알아야 할 것

**C (공고·추천)**
- 공고 테이블에도 `grade` 사용 시 `grade_column(Grade.PUBLIC)`, `grade_check()` 사용 가능
- C3 임베딩 메타데이터의 shared_with·expires_at은 `resumes.shared_with` 형식과 같게 맞추는 것을 권장
- 제안(참고용): 벡터 DB가 같은 PostgreSQL이므로 검색 필터에서 `shares` 테이블을 직접 조인하는 방법도 있음. 공유 취소·만료가 즉시 반영됨(spec 3.7). 채택 여부는 C팀 판단

**D (인프라·인증)**
- 등급 명칭이 D1 정의와 다르면 알려 주면 맞춤 (값 변경은 마이그레이션 1건)
