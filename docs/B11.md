## 1. 결과 요약

- A8 가드레일이 요청 종료 시 부르는 **감사 로그 기록 함수**(`AuditSink`)
- **운영자 전용 조회 API** (`GET /audit-logs`)
- 감사 로그 **수정·삭제 방지**(팀 합의 사항) + doc_ids·doc_grades 길이 일치 제약

## 2. 기록 함수 (A8 연결)

```python
from app.features.audit.sink import DbAuditSink

guard = Guardrail(..., audit=DbAuditSink())   # A8 이 요청마다 write(**fields) 한 번 호출
```

- 받는 키: A8 `_write_audit`의 필드 + `Verdict.to_audit_fields()` (spec 10.1)
- 저장 전 검증 → 어긋나면 예외 → A8이 `AuditWriteFailed`로 요청 실패 처리
  - 알 수 없는 키(원문 질의 등) 거부
  - 판정·역할·질의 유형 값, `query_hash` SHA-256 형식, 등급 값
  - `doc_ids`·`doc_grades` 같은 길이
  - **`session_id`가 `test-`로 시작 ⇔ `is_test=true`**
- 오류 메시지에 입력 값을 넣지 않음(민감 등급 데이터 보호)
- 요청 트랜잭션과 분리해 커밋 → 요청이 실패해도 감사 로그는 남음

## 3. 조회 API (운영자 전용)

`GET /audit-logs?from=&to=&user_id=&role=&feature=&query_type=&decision=&is_test=&limit=&offset=`

- **운영자 MFA 세션만**(D7 `require_operator_mfa`, 10/27 전환): 운영자 + TOTP 등록 + 최근 로그인(기본 15분). 그 외 역할 403, TOTP 미등록 403 `mfa_required`, 세션 만료 403 `mfa_session_expired`, 미로그인 401
- `request_id` 필터 추가(10/27, B16 평가 러너용)
- 최신순, 기본 50건, 최대 500건
- 기간은 `from` 이상 `to` 미만
- D15 대시보드·B16 평가 러너가 같은 API 사용. 집계 API는 두지 않음(문서대로)
- **`doc_ids`는 고아가 될 수 있음**: 감사 로그는 문서 삭제의 "참조"에 포함하지 않습니다(A·C 합의, 10/21). 참조한 문서(공고·자소서 등)가 나중에 물리 삭제되면 `doc_ids`의 ID는 더 이상 존재하지 않을 수 있습니다. 조회 API는 문서 테이블과 조인하지 않고 저장된 값을 그대로 돌려주므로 오류가 나지 않습니다. 대시보드·리포트에서 doc_id로 문서를 찾지 못하는 것은 정상입니다

## 4. 수정·삭제 방지 (DB 트리거)

| 동작 | 허용 조건 |
|---|---|
| 수정(UPDATE) | `user_id`를 `users.anon_id`에 있는 값으로 바꾸는 **익명화만**(B20). 다른 컬럼 변경은 거부 |
| 삭제(DELETE) | **90일이 지난 행만**(B3 보관 정리) |
| 전체 삭제(TRUNCATE) | 거부 |

- DB 관리자는 트리거를 끌 수 있으므로, 앱 DB 계정 권한 분리(D)와는 별개의 방어선

## 5. 다른 팀이 알아야 할 것

**A (가드레일)**
- 연결: `Guardrail(audit=DbAuditSink())`
- `is_test=True`이면 `session_id`는 `test-`로 시작해야 함(이미 전달). 어긋나면 요청 실패
- **확인 요청: 감사 로그의 `query_masked`에 개인정보가 남습니다.** A8이 `mask(query)`로 만든 값이 `"김철수 ***-****-5678 지원 동기 고쳐줘"`처럼 저장됨 → **이름이 가려지지 않고 전화번호 끝 4자리가 남음.** spec 15장 "감사 로그에 PII 유입" 리스크에 해당. A1 `mask` 동작 확인 부탁

**D (인프라)**
- **라우터 등록 요청**([D 리뷰 요청]): `app/app/main.py`는 D 소유이고 D3에서 `create_app()` 구조로 바뀌어, B는 수정하지 않았습니다. 아래 두 줄을 넣어 주세요.
  ```python
  from app.features.audit.router import router as audit_router
  application.include_router(audit_router)   # create_app() 안
  ```
  등록 전까지 `/audit-logs`는 앱에 노출되지 않습니다(기록 함수 `DbAuditSink`는 등록과 무관하게 동작). B 테스트는 테스트 앱에 라우터를 직접 붙여 검증합니다.
- 앱 DB 계정을 INSERT·SELECT로 제한하는 권한 분리는 D 영역(선택)

**B (평가 러너 B16)**
- 조회는 `is_test=true` + 기간 필터로 읽음

## 11/3 AI 사용 기록: 답변 기록·가린 자리 강조·판정 상세 (part2_guide 4.74)

- 배경: 화면의 답변이 항상 "(기록 없음)"이었음. 감사 로그에 답변 칸이 없었고 A8도 답변을 넘기지 않았음(10/29 결정 4.68의 남은 작업)
- 결정(11/3 사용자)
  - 답변: **개인정보만 가린 전체 답변** 저장(자르지 않음, spec 10.1·4.68 유지)
  - 차단: 막힌 모델 응답은 **기록하지 않음**(유출된 지침·타인 문서·카나리를 감사 로그에 다시 남기지 않게), 대신 차단 사유를 상세히
  - 가림: **가린 자리 강조 + 종류·단계** 표시, 원래 값은 보여 주지 않음
- 저장(A8 수정 — A8 수정 권한 허가 범위)
  - `PipelineResult.audit_response`: 출력 검사를 통과한 **복원 전** 응답(PII 토큰 상태). 분할 호출은 조각을 이어 붙임. 차단 시 빈 값
  - `_write_audit`이 `response_masked = mask(audit_response)`로 저장(모델이 지어낸 PII까지 질문과 같은 방식으로 한 번 더 가림). 사용자에게 돌려준 글은 복원본이지만 감사 로그에는 원문 PII가 남지 않음
- B 변경: `audit_logs.response_masked`(마이그레이션 0026, 수정 방지 트리거는 행 전체 비교라 새 칸도 보호), `AuditRecord`·조회 API에 칸 추가
- 화면(`features/audit/labels.js`)
  - 질문·답변의 가린 자리(`[[PHONE_1]]` 토큰, `***-****-****` 별표)를 '전화번호'·'이메일'·'이름' 등으로 강조 표시
  - 판정 상세: 단계(입력 검사/검색 결과 검사/출력 검사)와 그 단계에서의 뜻, 걸린 규칙을 한국어 설명 + 규칙 ID로, 가린 항목 종류별 개수, 카나리 감지 표시
  - 답변이 없는 경우: 차단은 "(차단되어 답변 없음)", 이 기능 이전 기록은 "(기록 없음 — 답변 기록 이전 요청)"
- 테스트: A8 2건(복원 전 토큰 + 마스킹으로 저장·원문 PII 없음, 차단 시 None), B11 2건(저장·조회, 수정 방지 대상에 새 칸 포함)
- 한계: 이 변경 이전 요청은 답변이 없음. 사람 이름은 A1이 토큰으로 바꾼 경우만 가려짐(질문의 `mask`와 같은 수준)

## 11/3 대화 묶어 보기(part2_guide 4.77)

- 요청(11/3 사용자): 같은 대화에서 오간 기록을 묶어서 보거나 대화 이름을 표기
- API: `GET /audit-logs?session_id=...` 필터 추가(감사 로그의 `session_id` 그대로, 1~128자)
- 화면: 세션이 있는 기록에 `대화 <기능> · <ID 앞 8자>` 칩(면접은 `면접 연습 · <면접 ID 앞 8자>`). 누르면 그 대화의 기록 전부를 **시간순**으로 모아 보고(필터와 무관, 최대 500건), `전체 기록으로`로 돌아간다. 기능 이름도 한글로 표시(D15 대시보드와 같은 이름)
- 세션이 있는 기능은 지금 면접(`interview-<면접 ID>`)뿐. 다른 기능은 화면이 `X-Session-Id`를 보내지 않아 단발 요청으로 남는다(칩 없음)
- 대화 이름에 자소서 제목은 쓰지 않음: 감사 로그에 없고, 운영자에게 사용자 자소서 제목을 노출하게 된다
- 테스트: `session_id` 필터(test_audit_b11), 로컬 API로 면접 세션별 조회 확인
