| 계정 | 삭제 요청 후 30일(유예 중 철회 가능) | 아래 순서. 유예 중에는 Cognito 비활성화로 로그인 차단 |

**계정 삭제 순서**
1. 감사 로그 `user_id` → 익명 토큰(`anon-…`)으로 치환해 **보존**(spec 10.2)
2. S3 `users/{id}/` 아래 파일 전부 삭제(DB보다 먼저 — DB 삭제가 실패해도 다음 배치가 다시 지움)
3. 사용자 데이터 키 폐기 → 백업에 남은 대응표도 복호화 불가
4. 사용자 행 삭제 → 소유 데이터 전부 DB 연쇄 삭제(자소서·경험·대응표·임베딩·공유·코멘트·지원 기록·말투 프로필·로드맵 등)
5. 이 사용자가 **멘토로 받은 공유**가 사라지므로, 작성자 자소서의 공유 복제본·검색 메타데이터 재동기화
6. **마지막에 Cognito 사용자 삭제**(`AdminDeleteUser`, D 요청 10/26). Cognito 삭제가 실패하면 그 계정의 DB 삭제도 되돌려 다음 배치가 다시 시도합니다. Cognito에 이미 없으면 삭제된 것으로 봅니다

**유예 중 차단(3중)**
- Cognito 비활성화 → 새 로그인 불가
- `require_active_account` → 이미 발급된 토큰으로 오는 요청 403(D7 연결 시 전 API)
- 멘토 열람 → 작성자가 삭제 예약 중이면 공유 자소서·코멘트가 404(작성자 본인 요청이 아니라 인증 단계로는 못 막는 부분, B10 저장소에서 처리)

**배치 규칙**(사용자 결정 10/26): 종류별 1회 최대 100건, 오래된 순. 건마다 별도 트랜잭션이라 한 건이 실패해도 나머지는 진행(실패는 로그·결과에 ID만)

## 2. 다른 팀이 쓸 함수 (`app/app/features/deletion/service.py`)

| 함수 | 용도 | 사용 |
|---|---|---|
| `request_account_deletion(db, user_id)` | 삭제 예약 + **Cognito 비활성화**(`AdminDisableUser`). 완전 삭제 예정 시각 반환. 이미 예약됐으면 처음 시각 유지. Cognito 실패 시 예외(예약도 되돌림) | D7 계정 삭제 API |
| `cancel_account_deletion(db, user_id)` | 유예 기간 안 철회 + **Cognito 다시 활성화** | D7 철회 API |
| `deletion_pending(db, user_id)` | 삭제 예약 중인가 | 아래 의존성이 사용 |
| `require_active_account` (`features/deletion/dependencies.py`) | FastAPI 의존성. 예약 중이면 403 `account_deletion_pending` | D7 인증 의존성에 연결(철회 API 제외) |
| `python -m app.features.deletion.service` | 배치 1회 실행. 실패가 있으면 종료 코드 1 | D5 CronJob(하루 1회 권장) |

## 4. 다른 팀이 알아야 할 것

**D**
- D5: CronJob으로 `python -m app.features.deletion.service` 실행(app 이미지, DB·S3·KMS 권한)
- D7: 계정 삭제 요청·철회 API에서 위 함수만 호출하면 됩니다. Cognito 비활성화·활성화·삭제는 B 함수 안에서 합니다(D의 `get_cognito_client`·username 조회 재사용)
- D7: 인증 의존성에 `require_active_account` 한 줄 연결(철회 API·`/auth/me` 제외 권장)
- IAM: 앱·배치 IRSA에 `cognito-idp:AdminDisableUser`, `AdminEnableUser`, `AdminDeleteUser`(+ 조회용 `AdminGetUser`, `ListUsers`)
- CronJob 실행 환경: app 이미지, DB·S3·KMS 권한, `COGNITO_USER_POOL_ID`·`S3_BUCKET_NAME`·`KMS_KEY_ALIAS` 등 앱과 같은 설정
- 유예 중에도 B API는 별도로 막지 않습니다(차단은 인증 단계에서 한 곳)

**C**
- 임베딩 삭제에 `delete_personal`을 씁니다(자소서·경험). 계정 삭제는 `user_profile_embeddings.owner_id` 연쇄 삭제로 처리됩니다
- 사용자가 직접 입력한 공고(`owner_user_id`)는 계정 삭제 시 함께 삭제됩니다(10/22 확인)
