### 10/27 개정: 04·05를 api로 바꾼 이유
- 멘토 공유 화면에는 AI(LLM) 기능을 두지 않는다(10/27 사용자 결정). 필요하면 작성자 쪽에 둔다
- 기존 04·05는 멘토용 AI 기능(`mentor.feedback`, 문서에 없는 잠정 이름)을 가정한 llm 시나리오였고, 실제 엔드포인트가 없어 러너가 글 다듬기로 대신 보냈다(검색 0건 확인도 불가)
- 같은 우회 의도(미공유 문서 요청, 공유 후 수정본 요청)를 멘토가 실제로 쓰는 API로 확인한다. 건수 5건 유지
- 1차 측정(round1)은 이전 형식으로 측정됨 → 리포트에 ※ 표시, 2차부터 새 형식

## 2. 형식 (A10·B18과 같음 + 경로 구분)

공유 우회는 대부분 AI를 거치지 않는 API 호출이라 `channel`을 둡니다.

| channel | 투입 | 판정 |
|---|---|---|
| `api` | `request: {method, path, body}`. path의 `{share_id}` 등은 시드 데이터로 채움 | 응답 코드. 404·403 → `block` |
| (llm) | B19에는 없음(10/27 개정) | — |

- `preconditions.share_state`: active / expired / revoked
- api 404는 존재 여부를 숨기므로 기대 안내 문구 없음(`message: null`)
- `response_excludes`: 응답 본문에 나오면 안 되는 문장(05: 공유 이후 수정본). 러너(B16)도 같은 검사를 하고, 대조 테스트로 실제 노출 시 불일치로 잡는지 확인
