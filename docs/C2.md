## 무엇 / 왜

`matrix.yaml`(역할×등급 매트릭스)을 읽어 **역할별 "검색 필터 조건"을 만들어 주는 공용 패키지.** C6 검색(WHERE 변환)과 A3 분류기(접근 판정)가 같은 로더를 쓴다. 매트릭스를 YAML 한 파일로 모아, 정책이 바뀌면 YAML만 고친다(spec 원칙 7).

매트릭스는 `spec §6.3`을 **로컬 `matrix.yaml` v0**로 옮겨 진행(D2 공식본 나오면 교체, 로더 코드는 그대로).

## 로직 / API

- **검색 가능 등급 = decision이 `allow` 또는 `mask`** (`block`은 제외). mask도 "검색은 되고 출력 때 A5가 가림"이라 필터엔 포함(C1 PoC와 동일).
- 등급별 scope: `own`=본인 소유 / `shared`=공유+만료 전 / `all`=조건 없음.

```python
Policy.load(path)
Policy.retrieval_filter(role, user_id) -> [GradeCond]   # C6용. role·user_id 필수
Policy.decision(role, grade) -> (decision, scope)        # A3용
build_where(conds, user_id=...) -> (sql, params)         # 파라미터 바인딩만(인젝션 방지)
```

## 결과

- `unittest` **17개 통과**.
- 생성되는 WHERE (C1 PoC에서 통과한 형태와 일치):
  - **user**: `공개 OR (개인 AND owner_id=:uid) OR (민감 AND owner_id=:uid)`
  - **mentor**: `공개 OR (개인/민감 AND :uid = ANY(shared_with) AND expires_at > now())`
  - **operator**: `공개/내부/개인/민감` (기밀만 제외, 소유 조건 없음)
- 등급·user_id 모두 **파라미터 바인딩** (SQL에 값 직접 안 박힘).
- 안전 기본값: 모르는 역할·등급 → `block`, 허용 등급 0개 → `WHERE FALSE`(결과 없음).

## 아직 안 정한 것

- **역할 값 표현**(`user/mentor/operator/system` vs 한글)·**등급 enum** → D1/B2 확정 시 `matrix.yaml`만 조정(로더는 값 불문).
- `matrix.yaml` 최종 위치 = `policy/matrix.yaml`(D2 소유).
- **PyYAML 의존** — nesume 통합 시 `requirements.txt`(D 소유)에 추가 필요. 로컬은 venv로 설치해 테스트.
- `내부` 등급은 RAG 인덱스가 없어(spec §6.4) C6 검색에선 사실상 공개/개인/민감만 걸림.
