## 무엇 / 왜

`matrix.yaml`(역할×등급 매트릭스)을 읽어 **역할별 "검색 필터 조건"을 만들어 주는 공용 패키지.** C6 검색(WHERE 변환)과 A3 분류기(접근 판정)가 같은 로더를 쓴다. 매트릭스를 YAML 한 파일로 모아, 정책이 바뀌면 YAML만 고친다(spec 원칙 7).

매트릭스는 `spec §6.3`을 **로컬 `matrix.yaml` v0**로 옮겨 진행(D2 공식본 나오면 교체, 로더 코드는 그대로).

## 로직 / API

- **검색 가능 등급 = decision이 `allow` 또는 `mask`** (`block`은 제외). mask도 "검색은 되고 출력 때 A5가 가림"이라 필터엔 포함(C1 PoC와 동일).
- 등급별 scope: `own`=본인 소유 / `shared`=공유+만료 전 / `all`=조건 없음.

```python
Policy.load(path)
Policy.retrieval_filter(role, user_id) -> [GradeCond]   # C6용. role·user_id 필수
Policy.decision(role, grade) -> (decision, scope)        # A3용
build_where(conds, user_id=...) -> (sql, params)         # 파라미터 바인딩만(인젝션 방지)
```

## 결과

- `unittest` **17개 통과**. **B2 실제 스키마에 맞춤**: 등급 값 영문(`public/personal/…`), 공유는 JSONB.
- 생성되는 WHERE (C1 PoC 형태 + B2 스키마):
  - **user**: `public OR (personal AND owner_id=:uid) OR (sensitive AND owner_id=:uid)`
  - **mentor**: `public OR (personal/sensitive AND EXISTS(SELECT 1 FROM jsonb_array_elements(shared_with) e WHERE e->>'user_id'=:uid AND (e->>'expires_at')::timestamptz > now()))`
  - **operator**: `public/internal/personal/sensitive` (confidential만 제외, 소유 조건 없음)
- 등급·user_id 모두 **파라미터 바인딩** (SQL에 값 직접 안 박힘).
- 안전 기본값: 모르는 역할·등급 → `block`, 허용 등급 0개 → `WHERE FALSE`(결과 없음).

## 아직 안 정한 것

- **등급 값**: B2 `Grade` enum(영문)에 맞춤 완료. **역할 값**(`user/mentor/operator/system`)도 main `app/app/auth/cognito.py`(cognito:groups)와 **일치 확인됨(2026-10-20)** — 더 이상 대기 아님.
- **공유 스키마 전제**: `shared_with`가 B2의 **JSONB `[{user_id, expires_at}]`**(resumes 전용)라고 가정. C3 임베딩 메타에도 같은 형태로 복제(denormalize)해야 이 WHERE가 벡터 검색에 그대로 적용됨.
- `matrix.yaml` 최종 위치 = `policy/matrix.yaml`(D2 소유).
- **PyYAML 의존** — ⚠️ C2는 이미 main에 머지됐으나 `requirements.txt`에 `pyyaml`이 **없음** → 컨테이너·CI에서 import/테스트 깨짐. **D에 `pyyaml==6.0.3` 추가 요청**(C2 코드는 손 안 댐). 현재 소비자 없어 당장 앱은 안 죽음.
- `내부` 등급은 RAG 인덱스가 없어(spec §6.4) C6 검색에선 사실상 공개/개인/민감만 걸림.
