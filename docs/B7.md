# [B7] PII 대응표 저장소 + KMS 암호화 — 완료 (자소서·경험 연결 포함)

- 담당: B (자소서 관리·문서)
- 완료일: 2026-10-20 (저장소), 2026-10-22 (자소서·경험 저장 경로 연결)
- 상태: 구현 완료, **A 리뷰 요청**
- 마이그레이션: `0008` 대응표·사용자 키, `0011` 버전·경험의 대응표 참조

---

## 1. 결정 사항

| 항목 | 결정 |
|---|---|
| 자소서 본문·경험 저장 | PII를 토큰(`[[PHONE_1]]` 등)으로 바꾼 상태로 DB 저장. 원문은 대응표에만 (A팀 논의 완료, 10/20) |
| 저장용 대응표 | **만료 없이 보관**, 문서 삭제 시 함께 삭제 |
| LLM 경로 대응표 | A1 기본값(30분) 그대로 |
| 토큰 범위 | 문서 단위(버전 1개, 경험 1개마다 대응표 1개, 번호는 1번부터) |
| 대응표 저장 시점 | 문서와 **같은 트랜잭션** — 문서 저장이 실패하면 대응표도 남지 않음 (10/22) |
| 자소서 본문 민감정보 | 경험과 같이 주민번호·계좌번호는 **저장 거부**(422, spec 9.1 문구) (10/22) |
| 경험 태그 필터 | 입력값 그대로 비교. 개인정보 없는 태그만 검색됨 (10/22) |

## 2. 구현 내용

**대응표 저장소** `app/app/pii/pg_vault_store.py` — A1 `VaultStore` 규약 구현

| 클래스 | 용도 |
|---|---|
| `PostgresVaultStore` | 작업마다 자체 세션·커밋. LLM 경로(30분 대응표)용 |
| `SessionVaultStore(db)` | 요청 세션을 그대로 사용(커밋은 요청 끝에). 자소서·경험 저장용 |

```python
from app.pii import tokenize, detokenize
from app.pii.pg_vault_store import PostgresVaultStore

store = PostgresVaultStore()
t = await tokenize(text, owner_id=user.sub, store=store)
d = await detokenize(t.text, t.vault_id, owner_id=user.sub, store=store)
```

- 원문 묶음은 **사용자별 데이터 키**로 AES-256-GCM 암호화. 데이터 키는 KMS로 발급하고 KMS로 암호화된 상태로만 저장
- 암호문을 다른 대응표·다른 사용자 행으로 옮기면 복호화 실패
- 만료된 대응표는 열 때 즉시 삭제 + 정리 명령 `python -m app.pii.pg_vault_store`(1회 최대 1,000행, 자동 실행 보류)
- 대응표는 **민감 등급**

**자소서·경험 연결** `app/app/features/resumes/pii_hooks.py`

| 경로 | 처리 |
|---|---|
| 저장 | A1 `validate_input`(민감정보 거부) → A1 `tokenize_fields(..., ttl_seconds=None)` → 대응표 저장 |
| 조회 | 소유자 본인일 때만 A1 `detokenize_fields`로 복원. 조사 보정 끔(원문 그대로) |
| 개인정보 없음 | 대응표를 만들지 않음(`vault_id` NULL) |
| 경험 수정 | 일부 필드만 바뀌어도 전체를 원문으로 되돌려 새 대응표로 다시 토큰화, 이전 대응표 삭제 |
| 버전 복원·비교 | 원문 기준. 복원본은 새 버전이므로 대응표도 새로 생성 |

- `versions.vault_id`, `experiences.vault_id` → `pii_vaults.id` (FK, 대응표는 참조 행을 먼저 지워야 삭제 가능)
- 글자 수(`char_count`)는 원문 기준

**사용자별 데이터 키** `app/app/pii/envelope.py`
- `destroy_user_key(db, user_id)`: 계정 삭제 시 키 폐기 → 백업에 남은 대응표도 복호화 불가(B20에서 사용)

## 3. 검증

- 전체 테스트 521건 통과
- 실제 A1 연동: 전화번호가 DB에는 `[[PHONE_1]]`로, 응답에는 원문으로 / 같은 번호는 문서 안에서 같은 토큰 / 경험 7개 필드 전부 토큰화 / 주민번호 입력 시 422·미저장·응답에 입력값 없음
- 경험 부분 수정 후 다른 필드 원문 유지 + 이전 대응표 삭제
- 참조 중인 대응표 먼저 삭제 시 거부, 계정 삭제 시 문서·대응표 함께 삭제
- 변이 검사 4종(민감정보 검사 제거, 이전 대응표 미삭제, 부분 수정 시 기존 필드 미복원, 복원 생략) 모두 테스트가 검출

## 4. 다른 팀이 알아야 할 것

**A (작성 AI)**
- A1 `tokenize_fields`(`ttl_seconds=None`) · `detokenize_fields`(`fix_particles=False`) · `validate_input` 사용. 리뷰 요청
- B7 파일은 A 소유 경로 `app/app/pii/`에 위치: `envelope.py`, `pg_vault_store.py`. B는 `__init__.py`를 수정하지 않음
- 작성 AI가 자소서 본문을 읽을 때 DB 값은 **토큰화 상태**. 원문이 필요하면 소유자 본인 요청에서 `vault_id`로 복원

**C (검색·공고)**
- 경험 태그 필터는 입력값 그대로 비교. 개인정보가 든 태그는 토큰 상태로 저장돼 검색되지 않음
- 개인 인덱스(C3)에 넣는 경험 값도 토큰화 상태

**D (인프라)**
- KMS 사용: `GenerateDataKey`, `Decrypt` (EncryptionContext `user_id`). 운영 IAM 권한에 필요
