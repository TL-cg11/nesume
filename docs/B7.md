## 2. 구현 내용

**대응표 저장소** `app/app/pii/pg_vault_store.py` — A1 `VaultStore` 규약 구현

```python
from app.pii import tokenize, detokenize
from app.pii.pg_vault_store import PostgresVaultStore

store = PostgresVaultStore()
t = await tokenize(text, owner_id=user.sub, store=store)            # 대응표가 DB에 암호화 저장
d = await detokenize(t.text, t.vault_id, owner_id=user.sub, store=store)
```

- 원문 묶음은 **사용자별 데이터 키**로 AES-256-GCM 암호화. 데이터 키는 KMS로 발급하고 KMS로 암호화된 상태로만 저장
- 암호문을 다른 대응표·다른 사용자 행으로 옮기면 복호화 실패
- 다른 소유자가 같은 대응표 ID로 덮어쓰기 불가
- 만료된 대응표는 열 때 즉시 삭제(A1 규약) + 정리 명령 `python -m app.pii.pg_vault_store`(만료분 1회 최대 1,000행, 자동 실행 보류)
- 대응표는 **민감 등급**

**사용자별 데이터 키** `app/app/pii/envelope.py`
- 사용자당 데이터 키 1개(`user_keys`)
- `destroy_user_key(db, user_id)`: 계정 삭제 시 키 폐기 → 백업에 남은 대응표도 복호화 불가(B20에서 사용)

## 3. 검증

- 단위 테스트 16건: 암호화 저장, 사용자당 키 1개, 만료, 암호문 이동 시 실패, 덮어쓰기 거부, 키 폐기 후 복호화 불가
- **실제 A1과 연동 확인**(A1 브랜치를 합친 임시 환경): `tokenize` → 저장 → `detokenize`로 원문 그대로 복원, 다른 소유자는 `VaultOwnerMismatch`, B+A1 테스트 201건 통과
- `ttl_seconds=None`은 A1 추가 기능 전이라 아직 `TypeError` (요청한 기능)
