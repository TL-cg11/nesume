# [B7] PII 토큰 매핑·KMS 암호화 — 보류 (A팀 확인 요청)

- 담당: B (자소서 관리·문서)
- 브랜치: `feat/part2-resume-docs`
- 상태: 설계 확정, **A팀 확인 후 구현**

## 확정된 내용

| 항목 | 결정 |
|---|---|
| 자소서 본문·경험 서술 저장 | PII를 토큰(`[PHONE_1]` 등)으로 바꾼 상태로 저장. 원문은 매핑 테이블에만 |
| 암호화 대상 | 매핑 테이블의 PII 원문 |
| 암호화 방식 | 사용자별 데이터 키(KMS 봉투 암호화). 계정 삭제 시 키를 폐기해 백업 속 데이터도 복호화 불가 |
| 복원 | 소유자 본인 요청일 때만 |
| 코드 위치 | `app/app/pii/` 하위 (A 소유 경로, A 리뷰 필요) |

## A팀에 확인 요청

**토큰 번호를 어떤 범위에서 매기나요?**

| 방식 | 의미 | 매핑 테이블 영향 |
|---|---|---|
| 사용자 단위 | 같은 사용자의 같은 전화번호는 어느 문서에서나 같은 토큰. 번호는 사용자별로 이어서 부여 | (사용자, 토큰) 기준. 계정 삭제 시 일괄 삭제 |
| 문서 단위 | 문서마다 `[PHONE_1]`부터 다시 시작 | (사용자, 문서, 토큰) 기준. 문서 삭제 시 해당 매핑도 삭제 |

A1의 `tokenize` 함수가 매핑을 저장할 때 B7 저장소를 호출하게 되므로, 함수 인자(사용자 ID, 문서 ID 포함 여부)도 같이 정해야 합니다.

## 현재 영향

- B4(자소서)는 본문 저장 경로에 PII 처리 지점만 두고 지금은 입력을 그대로 저장 중. A1·B7 추합 시 교체
