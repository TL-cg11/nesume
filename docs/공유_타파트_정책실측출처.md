## 1. 출처 (외부 데이터·API 현황)

| 출처 | 용도 | 상태 |
|---|---|---|
| **서울 열린데이터광장** (서울시 일자리포털 채용정보) | 공고 **주 출처** (추천·갭분석 본문) | 사용 가능 |
| 고용24 — 공통코드 | 지역·직종·NCS 코드 → 이름 변환 | 사용 가능 |
| 고용24 — 내일배움카드 훈련과정 | 학습 추천 | 사용 가능 |
| 고용24 — 직업정보 | 직업별 능력(보조 지표) | 사용 가능 |
| 고용24 — 직무정보(표준직무기술서·직무데이터사전) | NCS 역량 갭 | 사용 가능 |
| 고용24 — 공채속보 | 대기업·공공 공채(보조) | 사용 가능, 포함 미정 |
| 고용24 — 채용정보(구인공고) | — | **불가(개인회원 제한)** |
| 사람인 채용공고 | 전국·부족 직군(IT 등) 보완 | 승인 대기 |
| 임베딩 API | 공고·프로필 벡터화 | **모델 미정** |

> ⚠️ **출처 불일치(알아둘 것)**: 근거 문서(`spec §4.1`·`tasks C4`·`final §1`)는 공고를 **"고용24에서 6시간마다"**로 적지만, 실제 구현은 **"서울 열린데이터광장에서 하루 1회 전량 재수집"**이다(`Plan.md` v5). 고용24 채용정보가 **개인회원 호출 불가**라 전환했다. **접근 통제 설계에는 영향 없음**(공고는 어느 출처든 '공개' 등급). 수집 로직·주기·모델·화면 처리에만 영향.

**추가로 알아둘 것**

- **사람인**(승인 후 확인): 응답 본문 포함 여부·공고 ID·원문 링크·1일 한도·약관(저장·전송·출처) **미확인**. **사람인 없이도 동작하도록 설계**, 승인되면 출처에 추가. [C]
- **임베딩 API**: 모델이 정해져야 **벡터 차원 수(N)** 가 확정된다(공고·프로필 임베딩 컬럼) → **전 팀 영향(블로커)**. 개인·민감 등급은 **PII 토큰화 후** 전송. [전팀]

## 2. 정책 (약관·법무·보안 의무) — 타 파트 영향

**출처별 조건 (서로 다름)**

| 항목 | 서울 열린데이터광장 | 고용24 |
|---|---|---|
| DB 저장·가공·임베딩 | **가능**(공공누리 0유형) | 약관 불명확 → **문의 대기** |
| 외부 LLM·임베딩 전송 | **가능** | 제3자 제공 금지 소지 → **문의 전까지 소량만** |
| 상업적 이용 | 제한 없음 | **금지**(사전 동의) |
| 출처 표시 | **의무** — "서울특별시 공공데이터" (§10-3) | 의무 조항 없음(자체 표시) |
| 인증키 | 본인만 사용, 공유 금지 → **팀원 각자 발급** | 공유 금지, 1일 1만 쿼리 미만 |

**타 파트가 지켜야 할 의무**

- **출처 표시**: 공고 화면마다 "서울특별시 공공데이터". 원문은 변조 없이 표시하고 LLM 결과는 **"AI 분석 결과"로 구분**(서울시 §6-2 변조 금지). [B/화면]
- **상업적 이용**: 수익화 계획이 있으면 고용24 데이터(훈련과정·직무정보 등)는 **사전 동의 필요**. [공통]
- **정확성 책임 없음**(고용24 §21-8) → 화면에 출처·원문 확인 안내. [B/화면]
- **재배포 금지**: 수집 원본을 내려주는 공개 API·내보내기 기능을 만들지 않는다. [공통]

## 3. 실측 (측정 결과)

### 3.1 서울시 공고 데이터

| 항목 | 내용 |
|---|---|
| 규모 | 39,252건 (경기 ~24,000 / 서울 ~10,000 / 인천 ~5,000) → **수도권만** |
| 수집 | 1,000건/회, 횟수 제한 없음 → **하루 1회 40회 호출로 전량 재수집** |
| 식별 | **고유번호·수정일 없음** → 내용 해시로 신규·변경·삭제 판별 |
| 원문 링크 | **없음** → 접수방법(`RCPT_MTHD`) 표시 |
| 직무내용 | 전 공고 있음(평균 ~190자, IT ~420자) |
| 직종 편중 | 돌봄 36% / 사무 9% / 청소 8% … **IT 0.3%(123건)** → 추천 쏠림·IT 공고 희소 |
| 개인정보 | `CONTACT_TELNO`(~80%)·`EMP_CHARGER_DPT` → **수집 단계에서 버림** |

### 3.2 고용24 API 품질

- 데이터 규모: 훈련과정 ~11.6만, 공채속보 269, 직업정보 492, 코드(지역 285·직종 1,342·NCS 대분류 24).
- 품질 한계: **직무정보(표준직무기술서) 결과 부정확·빈 결과 잦음** → LLM 후보 선별 필요. 직업정보는 능력 수준이 거칢. 공채속보 상세 본문 빈약("모집요강 참조").

### 3.3 외부 응답 공통 특성 (전 API)

- **오류도 HTTP 200 + 본문 `<error>`/`{"error"}`**로 온다 → 상태코드 말고 **본문으로 성공 판정**, 오류를 정상 데이터로 저장 금지. [C]
- **XML 파서**: 외부 엔티티·DTD 비활성화(**XXE 방어**), 응답 크기 제한(직무정보 2종만 JSON, 나머지는 XML). [C/D]
- 응답에 **HTML·이미지**(훈련 `titleIcon`의 `<img>`, 공채속보 로고 http) → **저장·렌더링 안 함**, 텍스트로만. [B/화면]
- 훈련 과정/기관정보 담당자명·이메일·전화(`trprChap*`) → **저장 안 함**. [C]
- 공고 본문(`JOB_CONT`)에 **전화·이메일이 섞일 수 있음** → 외부 LLM·임베딩 전송 전 **PII 토큰화 대상**. [A]

## 4. 파트별 조치

### D 인프라·플랫폼·보안 ⚠️

- **인증키 로그 마스킹**: 서울시 키는 **URL 경로**(`/{키}/json/...`)+**http 평문** → 쿼리스트링 마스킹으론 안 걸림, **경로 기반 규칙 별도**. 고용24 `authKey`·사람인 `access-key`는 쿼리스트링 마스킹.
- **환경변수 등록**: `SEOUL_OPENAPI_BASE_URL`(`http://openapi.seoul.go.kr:8088`)·`SEOUL_OPENAPI_KEY`, `WORK24_*`(5종), `EMBEDDING_*` (+승인 시 `SARAMIN_*`).
- **수집 작업**: 서울시 수집은 **하루 1회** CronJob, http 평문이라 **서버 환경에서만** 실행. https 지원 여부 미확인.
- **SSRF**: 공고·훈련 원문 링크를 **서버가 직접 가져오지 않음**.
- **Rate Limit**: 고용24 **1일 1만건(5종 합산)** 상한 가정.

### B 자소서 관리·문서 (web 골격·화면)

- **"서울특별시 공공데이터" 출처 표시** 의무, 원문 무변조 + "AI 분석 결과" 구분.
- 응답 내 **HTML·이미지 렌더링 금지**(텍스트만). 외부 링크는 **고용24는 `https`+`work24.go.kr` 도메인만** 허용, 공채속보 기업 링크는 스킴만 허용 — 새 창 + `rel="noopener noreferrer"` + "외부 사이트" 표시.

### A 자소서 작성 AI

- 공고 본문 등 외부 텍스트는 **PII 토큰화(A1) 후** 외부 LLM·임베딩 전송, **인젝션 전처리(C5)** 적용.

### 공통

- 고용24 데이터 **DB 저장·외부 전송 허용 여부 문의 대기** → 답변 전 소량만. 수익화 시 **상업적 이용 동의** 필요.
