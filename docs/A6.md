## 1. 무엇을 하는가

에디터에서 **드래그한 구간**을 옵션에 맞춰 다시 쓴 **후보 3개**를 돌려준다.
고르기 전에는 본문이 바뀌지 않는다.

```
고른 구간  "협업으로 많은 성과를 내었습니다."      18자
옵션       합니다체 · 비슷하게 · 키워드: 협업

후보 1  협업으로 응답시간을 40% 단축했습니다.            22자 · 4자 늘어남
후보 2  협업을 통해 응답시간 40% 단축이라는 성과를 냈습니다.  31자 · 13자 늘어남
후보 3  동료와 함께 응답시간을 40% 줄였습니다.            23자 · 5자 늘어남

[이 후보로 바꾸기]  [새 버전으로 저장]
```

A7·A13 과 나누는 기준은 **무엇을 돌려주는가** 다.

| | 돌려주는 것 |
|---|---|
| A7 맞춤법·문장 개선 | 고칠 **자리**. 글은 사용자가 고친다 |
| **A6 리라이팅** | 고른 구간을 **통째로 다시 쓴 글**. 사용자는 고른다 |
| A13 글자 수·문체 조정 | 제한·문체라는 **기준에 맞춘 한 벌** |

## 2. ★ 후보 3개는 호출 **한 번**에서 받는다

후보마다 따로 부르면 3회다. 여기에 5,000자 분할이 곱해지면 A2 호출 상한
(`DEFAULT_MAX_CALLS` = 4)을 금방 넘는다.

조각 하나에 "후보 3개를 쓰라" 고 시키면 **호출 수가 조각 수와 같아진다.**

```
고를 수 있는 길이 = 5,000자 × 4조각 = 20,000자
호출 수          = 조각 수 (1~4회)
```

`MAX_PARTS` 를 `DEFAULT_MAX_CALLS` 와 같은 값으로 묶고 시험으로 고정했다.
더 크게 잡으면 조각을 만들어 놓고 `LlmBudgetExceeded` 로 거절당한다 —
**토큰은 이미 쓴 뒤다.**

## 3. ★ 가드레일에 **사용자 글**을 그대로 넘긴다

A7·A11·A13 은 프롬프트를 먼저 조립해서 `guard.run()` 에 넘긴다. 그러면 A3·A12 가
우리가 만든 템플릿까지 검사 대상으로 보게 되고, **문장 전체를 보는 규칙은 죽는다.**

> A12 `is_continuation` 은 `^...$` 앵커다. 템플릿에 싸이면 영원히 안 맞는다.
> `A10-MULTI-04`(나눠 묻기)가 1차 측정에서 통과하지 못한 원인이 이것이다.

A6 는 사용자가 고른 글만 넘기고, 조립은 A8 안쪽 `PartsBuilder` 에서 한다.
시험으로 고정했다 (`test_the_guardrail_sees_the_user_text_not_the_prompt`).

**기존 세 기능도 같은 모양으로 옮겨야 한다.** 범위가 커서 따로 고친다.

## 4. A8 에 분할 경로를 붙였다 (`run_split`)

A2 의 `generate_split` 은 "A6의 5,000자 초과 분할" 용으로 미리 만들어져 있었는데
파이프라인이 쓰지 않고 있었다.

| | 이유 |
|---|---|
| 검사는 **나누기 전에 통째로** | 조각낸 뒤 검사하면 경계에 걸친 민감정보를 놓친다. `010-1234` 와 `-5678` 로 갈리면 둘 다 전화번호가 아니다 |
| 조각내기는 **치환된 글** 기준 | 원문을 조각내면 토큰이 경계에서 잘려 복원되지 않는다. `[[PERSON_` 과 `1]]` 은 토큰이 아니다 |
| 한 조각이라도 막히면 **전부** 막는다 | 막힌 조각만 빼고 이으면 사용자는 **글 가운데가 사라진 줄 모른 채** 저장한다 |
| 감사 로그는 **한 줄** | 호출 수만큼 남기면 B21 집계가 그만큼 부푼다 |

입력 검사·분류·이력·치환은 `_before_llm` 하나로 묶어 `run` 과 `run_split` 이 같이
쓴다. **두 벌로 두면 언젠가 한쪽에만 검사를 더하게 되고, 그 한쪽이 열린 길이 된다.**

## 5. 지어내기를 막는 쪽으로 기울였다

리라이팅에서 가장 위험한 실패는 **분량을 맞추려고 사실을 만드는 것**이다.

- 길이 옵션은 **비율**로 적는다. "300자로 써라" 처럼 절대값을 주면 원문이 짧을 때
  없는 내용을 지어내 채운다. '길게' 에는 "없는 사실을 보태지 말라" 를 명시했다
- 키워드에는 "넣을 자리가 없으면 **억지로 넣지 않습니다**" 를 붙인다
- 조각에는 "앞뒤를 짐작해 **없는 내용을 덧붙이지 않습니다**" 를 붙인다
- 모델이 후보 형식을 어기면 **빈 결과**다. 응답 전체를 후보 하나로 치면
  사과문이나 설명문이 자소서 본문으로 저장된다

## 6. 다른 팀이 알아야 할 것

**B**

- 템플릿 이름은 **`rewrite-default`** 입니다 (B9 문서가 "A 가 정해 운영자에게 알려
  주세요" 라 해서 정했습니다). **변수 없는 템플릿**으로 약속합니다 — `render` 가
  변수 이름이 정확히 같기를 요구하는데 A6 가 채울 변수를 정해 두지 않았습니다.
  변수를 넣으시면 A6 가 그 템플릿을 쓰지 않고 내장 기본값으로 돕니다(화면에 안내).
- 활성 템플릿이 없어도 **기능은 돕니다.** 없으면 기능이 멈추게 두면 운영자가 첫
  템플릿을 등록하기 전까지 아무도 리라이팅을 못 씁니다.
- 저장은 `resumes.service.create_version(..., source="ai")` 를 부릅니다.
  `VersionCreate` 주석대로입니다.
- **요청 하나** — 자소서 문항 화면에서 글 다듬기로 넘어오는 링크에
  `?resume=<id>&question=<id>` 를 달아 주시면, 고른 후보를 그 자리에서 새 버전으로
  저장할 수 있습니다. 지금은 쿼리가 없으면 "이 후보로 바꾸기"(본문 치환)만 됩니다.

**C**

- 이 경로는 검색(C6)을 타지 않습니다. 사용자가 이미 쓴 글을 다시 쓰는 일이라
  참조할 바깥 문서가 없습니다. 쓸 일이 생기면 그때 붙입니다.

**D**

- `writing.rewrite` 가 감사 로그 `feature` 에 새로 들어갑니다.
- 분할 호출이어도 로그는 요청당 한 줄입니다.
