## 무엇을 검증했나

RAG 권한 필터가 **벡터 검색 쿼리 단계의 사전 필터**로 동작해, 금지 등급 문서가 애초에 top-k 후보에 못 들어오는지. (사후 필터는 top-k에 기밀이 들어왔다 빠지는 구조라 금지 — spec §8.2)

## 결과

| 테스트 | 내용 | 결과 |
|---|---|---|
| TEST 0 | 필터 없는 최근접 top-5 | 기밀·내부·타인 개인·만료 공유가 1~4위 → 사후 필터 누출 위험 **재현** |
| TEST 1 | 일반 사용자(userA) 사전 필터 | 공개 + 본인 개인/민감만. 기밀·내부·타인 개인 **전부 부재** |
| TEST 2 | 멘토 사전 필터 | 공개 + **유효 공유만**. 만료 공유·미공유·기밀 **전부 부재** |
| 자동 검증 | 누출 카운트 | `기밀/내부=0, 타인개인=0, 미공유=0` → **PASS** |
| TEST 3 | HNSW ANN 인덱스 + `iterative_scan=strict_order` | 동일하게 정확. `EXPLAIN`에 `Index Scan … Filter:` → **ANN 인덱스가 필터 적용** |

→ **누출 0, PASS.** 벡터 DB = **pgvector 0.8.7 확정**, 인덱스 **HNSW**.

## 실행 방법

팀 공용 스택을 건드리지 않도록 **격리된 임시 컨테이너**로 실행한다(끝나면 삭제).

```bash
POC=nesume-c1-poc
docker run -d --name "$POC" \
  -e POSTGRES_PASSWORD=pocpass -e POSTGRES_USER=poc -e POSTGRES_DB=pocdb \
  pgvector/pgvector:0.8.7-pg16-bookworm
# ready 대기 후
docker exec -i "$POC" psql -U poc -d pocdb -v ON_ERROR_STOP=1 < poc/c1_prefilter_poc.sql
docker rm -f "$POC"
```

## 운영 반영 (C2·C6 구현 시)

1. 벡터 DB = **pgvector 0.8.7**, 인덱스는 **HNSW**.
2. 검색 세션에 `SET hnsw.iterative_scan = 'strict_order'`(순서 보장) 또는 `'relaxed_order'`(성능 우선), `ef_search` 튜닝 — ANN 인덱스가 필터를 건너뛰어 금지 문서를 노출하는 위험을 막는 핵심 설정.
3. 필터 조건(WHERE)은 **C2 정책 로더**가 `matrix.yaml`에서만 생성. `search(query, role, user_id, top_k)` 외 경로는 제거(spec §8.2).
4. 공개/개인 인덱스 분리(**C9**)는 필터 버그 대비 2차 방어선.
