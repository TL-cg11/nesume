## 하는 일

`search(query, role, user_id, top_k)` — C2가 만든 권한 WHERE를 벡터 검색에 **강제**로 붙여, 금지 등급·타인 문서가 top-k에 애초에 안 들어오게 한다. 필터 없는 검색 경로는 제거(spec §8.2).

## PoC 결과 (2026-10-20)

C1은 손으로 쓴 WHERE였고, 여기선 **C2 `retrieval_filter`+`build_where`가 생성한 WHERE를 그대로** SQLAlchemy `text()`로 **실제 pgvector에 실행**했다. (격리 컨테이너, 가짜 4차원 벡터, 산출물 `poc/c6_retriever_poc.py`)

| 역할 | 기대 = 실제 |
|---|---|
| user/userA | 공개 + 본인 personal·sensitive만 (기밀·내부·타인개인 부재) ✅ |
| **mentor/m1** | 공개 + **유효 공유만**. 만료 공유·미공유 personal 부재 ✅ |
| operator/op1 | confidential 빼고 전부 (mask-all) ✅ |
| 필터 없음(대조) | 최근접 top-3 = confidential·internal·타인 personal → 사후 필터 위험 재현 |

**핵심 검증**: 멘토의 **JSONB `jsonb_array_elements(shared_with)` + `(e->>'expires_at')::timestamptz > now()`** 쿼리가 실제 pgvector에서 정확히 동작. 단위 테스트(문자열)로는 못 잡는 실행 단계까지 확인. → **C1(사전 필터 개념) + C2(WHERE 생성) + 실행이 end-to-end로 증명됨.**

## 아직 남은 것 (전체 구현)

- **실제 검색 대상 데이터** = C3 임베딩(벡터 테이블)·임베딩 모델 필요. PoC는 가짜 벡터.
- `search()` 모듈화 + 필터 없는 경로 제거(코드 리뷰 grep), 공개/개인 인덱스(C9) 적용.
- `hnsw.iterative_scan` 설정(C1 결론)으로 ANN에서도 필터 유지.
- **소프트 삭제 제외 (B 요청, 2026-10-20)**: resumes·experiences는 `deleted_at IS NULL`인 것만 검색. 임베딩은 **30일 후 물리 삭제** 때 지워지므로, 그 전까지 소프트 삭제분을 검색에서 걸러야 함(`docs/B4.md`·`B5.md`). → `search()` WHERE에 `deleted_at IS NULL` 추가(개인 인덱스 대상). 벡터 행에 `deleted_at` 메타를 복제하거나 원본 조인으로 확인.
