## 하는 일

문서를 벡터로 만들어 **등급·소유자·공유 메타와 함께** 저장하는 공용 인덱싱 파이프라인. C6 검색이 이 메타로 사전 필터링하므로 **메타가 벡터 행에 같이 실려야** 한다(spec §8.2). 벡터에 넣는 모든 문서(공고 수집 C4, 경험 B5, 자소서 B4)가 이 파이프라인만 쓴다(tasks 공통규칙 3).

## 인덱스 2개 (C9)

- **공개 인덱스** — 공고·학습 콘텐츠(`grade=public`). owner/shared 없음.
- **개인 인덱스** — 자소서·경험(`grade=personal`). `owner_id` 필수, 자소서는 `shared_with`(JSONB).

→ 필터 버그가 나도 공개 인덱스 검색에서 개인 문서가 안 나오게 **물리 분리**(2차 방어선).

## 벡터 행 메타 (C6 `build_where`가 그대로 적용되도록)

`grade`(영문) · `owner_id` · `shared_with`(JSONB `[{user_id, expires_at}]`, 자소서만) · `embedding vector(1024)`(bge-m3) · 원본 문서 참조.

- B2 문서 테이블의 grade/owner_id/shared_with를 **벡터 행에 복제(denormalize)** → C2가 만든 WHERE가 벡터 테이블에 바로 걸린다.
- **소프트 삭제(`deleted_at`)** — C6가 삭제된 자소서·경험을 검색에서 빼야 함(B 요청, 임베딩은 30일 후 물리 삭제). → `deleted_at`도 벡터 메타에 복제(삭제 시 B 동기화)하거나 검색 때 원본 조인.

## PII (spec §8.3 · A1 실제 API)

A1 공개 연산: `mask(text)`(복원 불가·동기·부작용 없음) · `tokenize(text, owner_id=, store=, ttl_seconds=)`(치환표 생성·async) · `detect(text)`(개수만).

- **공개(공고)**: 복원 불필요 → **`mask()`**, 호출은 수집 파이프라인(C4). 임베딩 텍스트는 사용자에게 안 보임.
  - ⚠️ `mask()`가 **끝 4자리·이메일 도메인**을 남김(로그 대조용) → 공개 인덱스 **저장**엔 과노출 가능. A에 "전부 가리기 옵션" 요청함(`docs/C_review_A1.md`). **A 응답 따라 적용.**
- **개인·민감(자소서·경험)**: spec §8.3은 **`tokenize`**(벡터엔 `[[PHONE_1]]` 토큰만). 단 TTL·복원 필요성은 아래 "아직 안 정한 것" 참조.
- 어느 경우든 **A1을 거친 텍스트만** 임베딩.

## 핵심 결정 (권고)

**공유 정보를 벡터 행에 복제 vs 검색 때 `resumes` 조인.**

- 권고: **복제(denormalize)** — spec §8.2 "메타데이터 사전 필터" 원칙, 검색이 벡터 테이블만 보면 됨.
- 비용: 공유가 바뀌면 **임베딩 행의 `shared_with`도 갱신**해야 함 (B10 노트에 "벡터 메타에도 반영" 이미 있음).

## 아직 안 정한 것 (팀 합의)

- **임베딩 모델 = `bge-m3` 확정 (N=1024, 로컬)** (2026-10-20). 남은 건 **D: 로컬 서빙 인프라**(torch+모델 ~GB → EKS 리소스/별도 임베딩 컨테이너, 안 되면 API 폴백). 로컬이라 **임베딩 시 PII 외부 전송 없음** → mask/tokenize는 저장·표시 보호용(아래 참조)
- **개인 문서 인덱싱: `tokenize` vs `mask`** — spec §8.3은 tokenize지만, A1 `tokenize`는 **TTL 30분 vault 전제**(LLM 요청 경로용)이고, **임베딩 텍스트는 사용자에게 안 보여줘 복원이 필요 없을 수** 있음. 복원 불필요면 `mask`로 충분(vault·B7 의존 제거). 필요하면 **장기 TTL + B7 `VaultStore`** 연동. → 결정 필요
- 자소서 임베딩 **단위** — 문항·버전별인지 자소서 단위인지 (B4 `versions` 구조와 연계)
- **재임베딩 트리거** — 공고 내용 변경(C4), 자소서 새 버전(B4), 경험 수정(B5)
- 공유 **복제 vs 조인** (위 권고 확정)

## 누가 봐야 하나

- **A** — A1 `mask`/`tokenize`/`detect`를 C3가 호출. 공개 저장용 "끝자리 전부 가리기" 옵션 요청(`docs/C_review_A1.md`).
- **B** — 문서 저장·변경·삭제 시 C3 파이프라인 호출: B5(경험→개인 인덱스), B4(자소서 버전), **B10(공유 변경→벡터 메타 동기화)**, B20(삭제→임베딩 삭제). **(개인 인덱싱에 tokenize 채택 시) B7 `VaultStore`·장기 TTL 필요.**
- **D** — 임베딩 API 키·모델(환경변수), 벡터 차원 결정 공유.
