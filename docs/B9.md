## 1. 결과 요약

리라이팅·분석·질문 생성에 쓰는 프롬프트를 **운영자가 버전 관리**합니다(spec 3.6).

| 규칙 | 내용 |
|---|---|
| 권한 | 운영자만 조회·생성·새 버전 작성(`require_role(OPERATOR)`). **활성 전환은 운영자 MFA 세션**(`require_operator_mfa`, D7). 그 외 역할은 403 |
| 수정 | 덮어쓰지 않고 새 버전(비활성)으로 저장. 이름별 활성 버전은 최대 1개 |
| 변수 | 본문에 `{{변수}}`. 저장할 때 본문의 변수와 변수 목록이 정확히 같아야 함(빠짐·남음·중복 → 422). 일반 중괄호(JSON 예시 등)는 그대로 |
| 등급 | 내부 등급(B8 자동). 검색 인덱스에 넣지 않고, 사용자에게 HTTP로 열지 않음 |
| A 읽기 | 같은 앱 안에서 함수로 활성 버전만 읽음(사용자 결정 10/27) |

## 2. API (운영자)

| 기능 | 주소 |
|---|---|
| 템플릿 목록(최신·활성 버전) | `GET /templates` |
| 새 템플릿(1버전) | `POST /templates` `{name, purpose, body, variables}` |
| 버전 이력 | `GET /templates/{name}/versions` |
| 새 버전 | `POST /templates/{name}/versions` `{body, variables, purpose?}` |
| 활성 전환(MFA) | `PUT /templates/{template_id}/activate` — C11-AUTHZ-07 주소 |

- 이름: 소문자·숫자·`_ . -`, 100자. 본문 최대 20,000자, 변수 최대 30개
- 오류 코드: `template_exists`(409), `template_variables_mismatch`(422, `errors.missing·unused`), `mfa_required`·`mfa_session_expired`(403, D7)

## 3. A(작성 AI)용 읽기 함수 (`app/app/features/templates/service.py`)

```python
from app.features.templates.service import get_active_template, render

t = get_active_template(db, "rewrite-default")   # 활성 버전 없으면 None → 기본 프롬프트로 대체할지는 A 판단
prompt = render(t, {"tone": "정중한", "length": "500"})  # 변수 이름이 정확히 같아야 함(빠짐·남음 → RenderValuesMismatch)
```
- 반환: `ActiveTemplate(name, purpose, version, body, variables)`. 새 버전은 운영자가 활성 전환하기 전까지 보이지 않습니다

## 4. 운영자 화면 (`web/src/features/templates/`, 메뉴 "프롬프트 템플릿")

- 목록(용도·최신 버전·활성 버전) → 선택하면 본문 편집 + 버전 이력
- 새 템플릿 / 새 버전 저장. 변수는 본문의 `{{변수}}`에서 자동으로 뽑아 표시
- 버전마다 "이 본문 불러오기", "활성 전환"(확인 창). MFA가 필요하면 안내 문구
- 운영자가 아니면 "운영자만 사용할 수 있습니다"
