## 2. 테이블

| 테이블 | 용도 | 비고 |
|---|---|---|
| users | 사용자 | id = Cognito sub. 역할은 저장하지 않고 토큰에서 읽음 |
| resumes | 자소서 | 소프트 삭제(`deleted_at`) |
| questions | 문항 | 글자 수 제한 |
| versions | 문항별 버전 | **수정 불가(INSERT만)**, 생성 방식 manual / ai |
| experiences | 경험 데이터 | 제목, 기간, 유형, 역할, 기술, 성과, 상세, 태그 |
| templates | 프롬프트 템플릿 | 이름별 활성 버전 1개 |
| shares | 멘토 공유 | 만료일 필수, 본인에게 공유 불가 |
| applications | 지원 기록 (기능은 C15) | 지원 시점 버전을 `version_ids`(문항별 버전 ID 배열)로 고정 참조, 자소서가 삭제돼도 기록 유지 |
| audit_logs | 감사 로그 | spec 10.1 필드 전체. 계정 삭제 후에도 보존 |

공통 규칙
- 모든 ID는 UUID
- 하위 테이블에도 `owner_id`를 둠
- 사용자 삭제 시 소유 문서는 함께 삭제, 감사 로그는 보존
- 값 목록이 문서에 정의된 컬럼만 DB에서 값 제한 (versions.source, applications.status, 감사 로그 enum)

## 4. 다른 팀이 알아야 할 것

**공통**
- 테이블 추가가 필요하면 모델을 B에 전달. 마이그레이션 파일은 B가 취합해 순서를 정리함
- 화면 추가: `web/src/features/<기능>/`에 페이지를 만들고 `web/src/app/routes.jsx`의 `featureRoutes`에 한 줄 추가
- API 호출: `web/src/app/api/client.js`의 `api.get/post/...`만 사용 (기준 경로 `/api`)

**A (작성 AI)**
- 감사 로그 `decision`은 `allow / block / mask` 3값 (spec 10.1). 표식은 `flags` 배열
- 리라이팅 후보 선택 시 새 버전 저장은 `versions` 테이블(B4 API 예정)

**C (공고·추천)**
- `applications.version_ids`: 지원 시점의 문항별 버전 ID 배열. 버전 압축 시 참조 중인 버전은 제외(B4)
- `applications.status` 값: applied / document_passed / interview / final / rejected (spec 4.5). 기본값 없음, 생성 시 지정
- `resumes.job_posting_id`, `applications.job_posting_id`의 공고 FK는 공고 테이블 생성 시 C가 추가

**D (인프라·인증)**
- 역할 값은 `user / mentor / operator / system`으로 잠정 사용 (D1 확정 시 맞춤)
- 웹 토큰 주입 지점: `client.js`의 `setTokenProvider()`, 401 처리 `setUnauthorizedHandler()`
- B가 D 소유 영역을 선행 작성함 → 리뷰 후 D로 이관
  - 테스트 하네스 (D3): `docker compose run --rm test`, 격리된 테스트 DB
  - Cognito JWT 검증 (D7 초안): `app/app/auth/`, 역할은 `cognito:groups`에서 읽음
  - `app/app/db.py` 제약 이름 규칙
