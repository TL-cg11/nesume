## 1. 결과 요약

- 파일을 비공개 S3에 KMS 암호화로 저장하는 모듈 (`app/app/core/storage/`)
- 다운로드는 S3 주소를 직접 주지 않고, 앱이 발급한 **1회용 토큰**으로 앱을 거쳐 전달
- 다운로드 토큰은 만료 24시간 후 자동 정리

## 2. 왜 Pre-signed URL이 아닌가

spec 3.2는 "Pre-signed URL 10분, **발급자 본인만**, **재발급 시 이전 URL 폐기**"를 요구함.
Pre-signed URL은 URL을 가진 사람 누구나 쓸 수 있고 특정 URL만 무효화할 수 없어 두 조건을 지킬 수 없음.
그래서 앱이 토큰을 발급하고 로그인한 발급자인지 확인한 뒤 파일을 전달하는 방식으로 구현함.

| 요구 (spec 3.2) | 구현 |
|---|---|
| 10분 유효 | 토큰 10분 |
| 발급자 본인만 | 다운로드 시 로그인 필수, 토큰 발급자와 같은 사용자만 성공 |
| 재발급 시 이전 URL 폐기 | 같은 파일로 재발급하면 이전 미사용 토큰 폐기 |
| (추가) 1회용 | 한 번 받으면 즉시 무효. 실패 시 재발급 필요 |

## 3. 사용 방법 (B12 PDF 등에서)

```python
from app.core.storage import objects, tokens

key = objects.user_object_key(user.sub, "resumes", str(resume_id), f"{doc_id}.pdf")
objects.put_object(key, pdf_bytes, "application/pdf")          # KMS 암호화 저장
token, expires_at = tokens.issue(db, user.sub, key, "자소서.pdf", "application/pdf")
# 화면: 로그인 상태로 GET /downloads/{token} 호출 → 파일 저장
```

- 객체 키는 `users/{user_id}/...`만 허용, 구성 요소는 영숫자·`.`·`_`·`-`만 (이름 등 PII 금지)
- 다운로드 파일명(한글 가능)은 토큰 발급 시 지정, 응답 헤더로만 전달
- 실패(무효·만료·사용됨·타인)는 모두 404, 이유를 알려주지 않음

## 4. 토큰 저장과 정리

- 토큰 원문은 저장하지 않고 SHA-256 해시만 저장 → DB가 유출돼도 토큰 사용 불가
- 정리 배치: 만료 후 24시간이 지난 토큰을 **오래된 것부터 1회 최대 1,000행** 삭제
  - 실행: `python -m app.core.storage.cleanup`
  - 1시간마다 실행 권장(한 번에 대량 삭제하지 않아 DB 부하 분산)

## 5. 다른 팀이 알아야 할 것

**D (인프라)**
- `app/app/core/storage/`는 tasks B6 산출물 경로이지만 디렉터리 소유 표상 D 영역 → 리뷰 요청
- 정리 배치 스케줄링 요청: K8s CronJob(D5), 1시간마다 `python -m app.core.storage.cleanup`
- `app/app/main.py`에 다운로드 라우터 등록 한 줄 (D 소유, 리뷰 요청)
- 파일 다운로드 트래픽이 app을 거침 (자소서 PDF는 수백 KB 수준이라 부담 작음)

**웹 화면 (각 팀)**
- 브라우저 링크로는 로그인 헤더를 보낼 수 없으므로 `fetch`로 받아 저장해야 함 (B12에서 공통 함수 추가 예정)
