## 1. 결과 요약

| 항목 | 내용 |
|---|---|
| 화면 | 메뉴 '면접 연습'(`/interview`). 자소서·주 질문 수 → 모의 면접 시작 → 채팅. 왼쪽 지난 면접 목록, 끝나면 채팅 옆에 피드백·예상 질문. `?resume=&session=`으로 바로 열기 |
| 면접관 | 실무 / 인성 / 압박 3종 중 **시작할 때 무작위**, 그 면접 동안 유지. 사용자 선택 없음(11/2 사용자 결정). 진행 중에는 유형을 숨기고 끝난 뒤 공개 |
| 진행 | 주 질문 **3~7개(기본 5)**, 주 질문마다 **꼬리 질문 최대 2개**. 면접관이 답변을 보고 [꼬리](방금 답변 파고들기) / [다음](아직 다루지 않은 주제의 새 주 질문)을 고르고, 상한은 서버가 강제. 마지막 주 질문 뒤 마무리 → 자동 종료. 사용자 중간 종료 가능 |
| 피드백 | **면접이 끝난 뒤에만**(대화 중에는 평가하지 않음): 구조·구체성·일관성·질문별 한 줄 평가·제안 |
| 예상 질문 | 면접과 **별개로** 자소서·경험에서 뽑은 예상 질문 **10개**(11/2 사용자 결정): 분야에 국한하지 않고 다양하게(지원 동기·경험 검증·직무·협업·가치관·입사 후 계획 등), **나올 가능성이 높은 순서**, 같은 내용 반복 금지. 종료 후 피드백과 함께 표시 |
| 참고 자료 | 고른 자소서의 문항별 최신 버전 + 그 문항에 연결한 경험만(소유자 조회 함수). 자소서 6,000자·경험 3,000자·대화 8,000자(오래된 것부터 뺌) |
| 질문 유형 선택 | 없음(11/2 사용자 결정) — 방향은 페르소나가 정함 |
| 가드레일 | 모든 LLM 호출은 A8 `Guardrail.run`(feature=`interview`). 자료·대화는 울타리로 감싸 데이터로만. 세션 헤더가 없으면 `interview-{면접 ID}`로 A12 멀티턴 방어에 묶음. 시스템 계정 403 |
| 민감정보 | 답변은 모델에 보내기 **전에** A1 판정, 주민번호·계좌번호 등이면 422(spec 3.3). 저장은 토큰화 + 대응표, 본인에게만 원문 |
| 등급·공유 | 두 테이블 개인 등급(B8). 멘토 공유 제외(spec 3.7) |
| 삭제 | 면접 삭제 시 대화·대응표 즉시 삭제. 자소서·계정 삭제 시 CASCADE, B20 자소서 물리 삭제가 대응표 정리 |

## 2. API (`/resumes/{rid}/interviews`, 자소서 라우터에 포함)

| 메서드·경로 | 내용 |
|---|---|
| `GET /` | 면접 목록(최신순): 상태, 답변 수, 피드백 여부, 끝난 면접의 면접관 유형 |
| `POST / {main_count}` | 시작 → `{session, llm_unavailable, blocked_reason}`. 면접관 인사 + 첫 주 질문 |
| `GET /{sid}` | 대화·진행(main_no, follow_used)·(종료 후) 피드백·예상 질문 |
| `POST /{sid}/answers {answer}` | 답변 → 면접관 다음 말. 마지막이면 종료 + 피드백 |
| `POST /{sid}/finish` | 사용자 종료. 답변이 있으면 피드백 |
| `POST /{sid}/feedback` | 피드백 다시 받기(종료 때 모델을 못 불렀을 때) |
| `DELETE /{sid}` | 삭제 |

## 3. 실패 처리

| 상황 | 시작 | 답변 | 종료·피드백 |
|---|---|---|---|
| 모델 없음 | 면접 안 만듦, `llm_unavailable` | 이번 턴 저장 안 함(같은 답변 다시 보내기) | 면접은 끝, 피드백 없음 → 다시 받기 |
| 가드레일 차단 | 면접 안 만듦, `blocked_reason` | 이번 턴 저장 안 함 | 피드백 저장 안 함 |
| 동시에 두 답변 | — | 409(행 잠금·순번 확인) | — |
| 끝난 면접에 답변 | — | 409 | 진행 중 피드백 요청 409 |

## 4. 저장 구조(마이그레이션 0024)

- 0023의 질문 목록 방식(`interview_questions`, `practice_answers`)은 대응표와 함께 삭제(11/2 사용자 결정 "오늘 작업한 것은 삭제")
- `interview_sessions`: resume_id, version_ids(시작 때 쓴 버전), persona, main_count, status(active/finished), feedback·expected_questions(토큰화, 대응표 공용), finished_at
- `interview_messages`: session_id, seq(순번, 유일), role(interviewer/candidate), kind(main/follow_up/closing), body(토큰화), vault_id
- 진행 상태(몇 번째 주 질문, 꼬리 수)는 메시지에서 계산(따로 저장하지 않음)
- downgrade는 대화형 기록을 지우고 0023 테이블을 빈 상태로 다시 만듦

## 7. 11/2 dev 확인 후 수정: 면접관이 엉뚱한 말을 하던 문제

dev 대화에서 확인한 현상과 조치

| 현상 | 원인 | 조치(B) |
|---|---|---|
| 면접관이 지원자 답변까지 지어내 자기 질문에 스스로 답함 | 역할 규칙이 약하고, 대화 기록 마지막의 답변이 눈에 띄지 않음 | "지원자 답변을 대신 만들지 말 것" 규칙. 모델이 `지원자:` 줄을 쓰면 그 앞에서 자름, `면접관:` 접두어 제거 |
| "싫어요", "엥" 같은 답에도 "구체적으로 설명해 주셨지만…"처럼 하지 않은 말을 했다고 함 | 방금 답변이 대화 기록 속에 섞여 있었음 | **방금 답변을 따로 울타리로** 넘기고 "답변에 실제로 있는 내용만 근거로" 규칙. 회피·무관·너무 짧은 답은 짧게 짚고 다시 묻거나(꼬리 남았을 때) 다음으로 |
| 협업 질문의 꼬리 질문이 이전 주제(캐시)로 돌아감, "성격의 장단점을 물었다"는 등 진행을 지어냄 | 진행 정보가 숫자뿐 | **지금까지 한 주 질문 목록·지금 주 질문·이 주 질문의 꼬리 질문**을 명시, "이전 주제로 돌아가지 말 것" |
| 꼬리 질문이 앞 질문에 조건을 덧붙이며 점점 길어짐 | 길이 제한 없음 | 1~3문장·200자 안팎 규칙, 반복 금지, 서버 상한 500자 |
| 시작 때 "다섯 가지 주제에 대해…"처럼 계획을 말함, "여러분" 호칭 | 시작 프롬프트 | 시작 전용 프롬프트(계획 미리 말하지 않기), 호칭 "지원자님" |

B 범위 밖(A 모듈, 재현 확인 후 전달 필요)
- A1 `validate_input`이 하이픈 없는 계좌번호(예: 14자리 숫자)를 통과시킴 → 답변 민감정보 차단(spec 3.3)이 이 형식은 못 막음
- A1 `detokenize_fields(fix_particles=True)`가 관형형 '-는'을 조사로 보고 '-은'으로 바꿈('있는'→'있은', '필요없는'→'필요없은'). A8이 모델 응답 복원에 쓰므로 자소서에 개인정보가 있으면 면접관 말에 나타남. A #49(맞춤법 검사)와 같은 원인

## 8. 11/2 페르소나 상세화

`service.PERSONAS`(이름, 설정). 설정은 배경·말투·질문 초점·꼬리 질문 방식·부실한 답 대응 다섯 항목이며, 시작·매 턴 프롬프트 맨 앞에 "아래 설정대로 말하고 질문하세요"와 함께 들어간다.

| 페르소나 | 배경 | 말투 | 질문 초점 | 꼬리 질문 | 부실한 답 |
|---|---|---|---|---|---|
| 실무 면접관 | 지원 직무 팀 7년 차 현업 리더(함께 일할 동료를 뽑음) | 차분·정중한 존댓말, 칭찬·감탄 없음 | 기술·도구 선택 이유와 대안, 원인 분석 과정, 본인 일과 팀 일 구분, 결과 수치와 측정 방법 | 방금 답에서 한 단계 더(왜 그 방법, 다른 방법, 측정 방법) | 구체적인 예 하나 요청 |
| 인성 면접관 | 인사팀 10년 차 채용 담당(조직 적합성·성장 가능성) | 부드럽고 따뜻한 존댓말, 첫 질문에 긴장 풀어 주는 짧은 말 허용 | 지원 동기, 가치관, 협업·갈등, 실패·극복, 스트레스 관리, 성장 계획 | 판단 이유, 주변 반응, 다시 그 상황이면 | 실제 상황 하나 떠올리도록 부드럽게 요청 |
| 압박 면접관 | 최종 면접 임원(압박 속 논리 유지 확인) | 짧고 단호한 존댓말, 공감·맞장구 없음, 예의 유지·인신공격·비하 금지 | 허점, 근거 부족, 자소서와 불일치, 과장 가능성, 반대 가정 | 반박하며 검증(팀 일 vs 본인 일, 수치 근거) | 답이 아니라고 분명히 말하고 다시 요구 |

공통 규칙 추가: 나이·성별·출신 지역·가족·외모·종교·혼인 등 직무와 무관한 개인 사항은 묻지 않는다(채용 절차상 금지 질문).
