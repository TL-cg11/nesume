## 1. 결과 요약

| 항목 | 내용 |
|---|---|
| 화면 | 메뉴 '면접 연습'(`/interview`, B1 자리 표시 화면을 채움). 자소서 선택 → 유형·개수 → 질문 목록 → 질문별 답변·피드백·연습 기록. `?resume=<id>`로 바로 열기 |
| 질문 생성 | `POST /resumes/{id}/interview/questions {type, count}` → `{questions[], llm_unavailable, blocked_reason}` |
| 유형·개수 | 인성(personality) / 직무(job) / 경험 검증(experience), **1~10개, 기본 5**(11/2 사용자 결정) |
| 참고 자료 | **고른 자소서의 문항별 최신 버전 + 그 문항에 연결한 경험만**(11/2 사용자 결정). 소유자 조회 함수로만 읽어 본인 자료로 한정. 자소서 6,000자·경험 3,000자에서 자름. 벡터 검색은 쓰지 않음(임베더 상태와 무관) |
| 답변 연습 | `POST .../questions/{qid}/answers {answer}` → `{answer, llm_unavailable, blocked_reason}`. 답변 3,000자까지 |
| 피드백 | **구조·구체성·일관성 코멘트 + 제안**(점수 없음, 11/2 사용자 결정). 일관성은 질문을 만들 때 쓴 버전과 비교(지워졌으면 지금의 최신) |
| 조회·삭제 | `GET .../questions`(최신순, 연습 횟수), `GET .../questions/{qid}/answers`(최신순), `DELETE .../questions/{qid}`(연습 기록 포함 즉시 삭제) |
| 가드레일 | 모든 LLM 호출은 A8 `Guardrail.run`만 사용(feature=`interview`, 감사 로그는 A8이 기록). 자료는 울타리로 감싸 데이터로만 전달. 시스템 계정은 403(D7 require_interactive) |
| 민감정보 | 답변은 **모델에 보내기 전에** A1으로 판정해 주민번호·계좌번호 등이면 422(spec 3.3). 저장은 B4·B7과 같이 토큰화 + 대응표, 본인에게만 원문 |
| 등급·공유 | 두 테이블 모두 개인 등급(B8 등급표에 추가). 자소서 복제본·공유 화면에 들어가지 않음 → 멘토 공유 제외(spec 3.7) |
| 삭제 | 자소서·계정 삭제 시 CASCADE. B20 자소서 물리 삭제가 면접 질문·답변 대응표도 정리 |

## 2. 실패 처리

| 상황 | 질문 생성 | 답변 |
|---|---|---|
| 모델 없음(LlmUnavailable) | 200, `llm_unavailable: true`, 저장 없음 | 답변만 기록(feedback null), `llm_unavailable: true` |
| 가드레일 차단 | `blocked_reason`, 저장 없음 | `blocked_reason`, 저장 없음 |
| 모델이 형식을 안 지킴 | 질문을 하나도 못 읽으면 502, 저장 없음 | 네 칸을 못 읽으면 응답 전체를 '제안'에 |
| 본문 없는 자소서 | 422 | — |
| 남의 자소서·질문 | 404 | 404 |

## 3. 설계 메모

- LLM을 기다리는 동안 DB 커넥션을 잡지 않음: 읽기 → LLM → 쓰기를 짧은 세션으로 나눔(A11 matching과 같은 원칙). 생성·답변 두 엔드포인트만 해당, 조회·삭제는 일반 요청 세션
- guide 초안의 `question_enc`·`answer_enc`·`feedback_enc`는 B7 결정(4.6·4.8)에 따라 **토큰화 본문 + vault_id**로 대신함(다른 B 테이블과 같은 방식)
- `interview_questions.version_ids`는 FK 없는 배열(shares·applications와 같은 방식)
- 마이그레이션 번호: C #47이 0022를 써서 0023. B11 감사 로그 답변 칸은 0024로 이어감
