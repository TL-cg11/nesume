## 1. 무엇을 돌려주는가

```
원문 117자 (공백제외 92) / 제한 60자 → 57자 초과
문체: 합니다체 · 혼용=True · 목표 외 문장 1개
    └ 그리고 끝까지 해냈어요.  (해요체)

규칙 제안 8건, 26자 절약 → 91자 (제한 충족=False)
    ST_FILLER    - 6  '개인적으로 ' → ''
    ST_VERBOSE   - 4  '하게 되었습니다' → '했습니다'
    ST_HEDGE     - 6  '이라고 생각합니다' → '입니다'
    ...

모델 호출 1회
다시 쓴 글: 협업으로 응답시간을 40% 단축했습니다. 끝까지 해냈습니다.   33자 · 합니다체
```

## 2. ★ 글자 수는 B4 와 같은 기준으로 센다

```python
# app/app/features/resumes/service.py (B 소유)
# 글자 수는 사용자가 입력한 원문 기준(공백 포함)
char_count=len(body)
```

**A13 이 "맞습니다" 라고 한 글이 저장할 때 제한을 넘으면 사용자는 A13 을 믿지 않는다.**
그래서 `len(원문)`(공백·줄바꿈 포함)으로 센다. 공백을 뺀 수는 참고로만 함께 돌려준다.

### 토큰화된 본문을 세면 틀어진다 — 거절한다

저장된 `versions.body` 는 **PII 토큰화 상태**다(`[[PHONE_1]]`). 값마다 길이가 달라
세면 저장될 수와 다른 수가 나온다. B 도 `char_count` 는 토큰화 **전** 원문으로 센다.
그래서 토큰이 섞인 글은 `TokenizedTextError` → **422** 로 거절한다. 조용히 세면
**사용자에게 틀린 수를 보여주고** 그 수를 믿게 만든다.

## 3. ★ 모델은 글자 수를 세지 못한다 — 서버가 다시 센다

"900자로 줄여라" 는 모델이 가장 자주 틀리는 지시다. 토큰 단위로 생성하므로 **글자를
셀 수가 없다.** 그래서 응답을 받으면 서버가 다시 센다.

```
모델 응답 → 머리말 제거 → 숫자 검사 → 길이 재측정 → 문체 재판정
                                          ↓ 안 맞으면
                                     한 번 더 요청 (최대 2회)
                                          ↓ 그래도 안 맞으면
                                     버리고 이유를 돌려준다
```

**맞지도 않는 글을 "줄였습니다" 로 내보내면 사용자는 저장 단계에서 거절당한다.**
`rejected_reason` 에 "68자로 줄어들어 아직 8자 넘습니다" 처럼 그대로 적어 보여준다.

`MAX_REWRITE_ATTEMPTS = 2` 다. 상한이 없으면 모델이 못 맞추는 글에서 호출이 계속 늘어난다
(A2 호출 상한은 4회).

## 4. ★ 새로 생긴 숫자가 있으면 통째로 버린다

자소서에서 가장 위험한 환각은 **성과 수치**다.

```
원문: 응답시간을 40% 단축했습니다
모델: 응답시간을 60% 단축해 비용 1,200만원을 절감했습니다
                 ^^^            ^^^^^^^ 원문에 없다
→ 응답 전체를 버린다.  rejected_reason = "원문에 없는 숫자가 들어가 버렸습니다 (1200, 60)"
```

**다시 쓰기는 글 전체가 바뀌므로 일부만 믿을 수 없다.** 그리고 이 경우에는 **다시 묻지
않는다** — 같은 사실을 또 만든다. 자리수 구분 쉼표는 지우고 비교해 `1,200` 과 `1200` 을
같게 본다.

> A11 은 "사용자 글·경험에 없는 **기술**이 나오면 버린다", A13 은 "원문에 없는 **숫자**가
> 나오면 버린다". 같은 생각을 각 기능이 다루는 재료에 맞춘 것이다.

## 5. ★ 모자란 분량은 채워 주지 않는다

최소 글자 수에 미치면 **질문만** 돌려준다. 분량을 모델에게 채우게 하면 **없는 경험을
지어낸다** — A7(STAR 보완)·A11(빠진 요건)과 같은 판단이다.

```
- 결과를 숫자로 적을 수 있습니까? (예: 응답시간 40% 단축, 참여 인원 12명)
- 그 일에서 **본인이** 한 행동은 무엇이었습니까? 팀이 한 일과 구분해 적어 보십시오.
- 그 경험에서 무엇을 배웠고, 지원하는 일과 어떻게 이어집니까?
```

테스트로 **"분량이 모자라면 모델 호출 0회"** 를 고정했다.

## 6. 문체 혼용은 맞춤법 검사로 잡히지 않는다

```
"저는 책임감이 강합니다. 그래서 끝까지 해냈어요."
                 ^^^^ 합니다체        ^^^^ 해요체
```

**두 문장 모두 맞는 문장**이라 A7 맞춤법 검사에서는 아무것도 나오지 않는다. 읽는 사람에게는
급하게 이어 붙인 글로 보인다. 그래서 A13 이 문장별로 어미를 보고 네 가지로 판정한다 —
합니다체 / 해요체 / 했다체 / 음슴체. 목표 문체가 아닌 **문장만 짚어** 돌려준다.

### 판정 순서가 곧 우선순위다

`입니다` 는 `다` 로 끝난다. **했다체 규칙이 먼저 보면 합니다체 문장이 전부 했다체로 잡힌다.**
A1 PERSON·A3 질의 분류에서 반복됐던 그 문제라, 처음부터 `formal → polite → nominal → plain`
순으로 두고 테스트로 고정했다.

제목처럼 명사로 끝나는 줄은 **판정 불가**로 두고 비율 계산에서 뺀다 — 섞인 것으로 세면
멀쩡한 글이 혼용으로 나온다.

## 7. 줄이기 규칙은 "사실을 지우지 않는 것" 만

줄이기는 **본문을 삭제하는 일**이라 환각보다 위험하다. 모델이 지어낸 것은 검증으로 걸러낼
수 있지만, **규칙이 지운 문장은 사용자가 알아채지 못하면 그대로 제출된다.**

| 종류 | 예 | 잃는 것 |
|---|---|---|
| 공백·줄바꿈 정리 | `"했고   그래서"` → `"했고 그래서"` | **없음** |
| 늘어진 표현 축약 | `"하게 되었습니다"` → `"했습니다"` | 없음 |
| 군더더기 부사 | `"매우 많은"` → `"많은"` | 어감 (그래서 `medium` 신뢰도) |

**문장·절을 통째로 지우는 규칙은 넣지 않았다.** 무엇이 덜 중요한지는 글쓴이만 안다.
규칙으로 모자라면 모델에게 다시 쓰게 하고 그 결과를 검증한다.

적용은 **뒤에서 앞으로** 한다(앞에서부터 바꾸면 뒤 제안의 위치가 밀린다). 받은 뒤 글을
고쳤으면 **409**, 겹치는 제안을 동시에 수락하면 **400** — A7 `/writing/apply` 와 같은 규약이다.

## 8. 구현 중에 잡은 버그

### `"강점이라고 생각합니다"` → `"강점이입니다"`

`[라이]고\s*생각합니다` → `입니다` 로 뭉쳐 놨더니 **받침 뒤의 `이`(계사)를 남긴 채** 치환해
`강점이입니다` 가 됐다. 둘로 쪼갰다.

```
이라고 생각합니다   → 입니다        "강점이라고 생각합니다" → "강점입니다"
(?<!이)라고 생각합니다 → 라고 봅니다
```

`"중요하다고 생각합니다"` 처럼 **형태소 분석 없이 줄이면 문법이 깨지는 것은 건드리지 않는다.**

### `"저는 개인적으로"` 에서 주어까지 지웠다

`(?:저는\s*)?개인적으로\s+` 로 둬서 **주어를 함께 삭제**했다. 한국어는 주어 생략이 자연스러워
문법은 안 깨지지만, **글쓴이가 알아채기 어렵다.** `개인적으로` 만 지우도록 좁혔다.

> **교훈: 치환 규칙은 "무엇을 남기는가" 를 먼저 정해야 한다.**
>
> 두 버그 모두 **치환 대상에 남겨야 할 것이 섞여 있었다.** A1 PERSON 규칙에서 구분자를
> 선택으로 둬 조사를 이름으로 먹던 것과 같은 모양이다. 치환 정규식을 쓰는 곳
> (C5 중화, A1 마스킹, B4 요약)은 매칭 범위를 한 번씩 확인해 보면 좋겠습니다.
