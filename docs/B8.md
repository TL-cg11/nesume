## 1. 결과 요약

spec 6.4 기능별 등급을 **저장할 때 자동으로** 붙이고, 이후 바꾸지 못하게 했습니다.

| 테이블 | 등급 |
|---|---|
| `resumes`, `questions`, `versions` (자소서) | 개인 |
| `experiences` (경험) | 개인 |
| `applications` (지원 기록) | 개인 |
| `templates` (프롬프트 템플릿) | 내부 |
| `pii_vaults` (PII 토큰화 전 원문) | 민감 |
| `audit_logs` (감사 로그) | 민감 |

## 2. 동작

| 상황 | 결과 |
|---|---|
| 새 행 저장 | 코드가 넘긴 값과 관계없이 위 표의 등급으로 저장 |
| 기존 행의 등급 변경 | `GradeChangeForbidden` 예외 |
| 일괄 INSERT·UPDATE 문(`session.execute`)에 다른 등급 | `GradeChangeForbidden` 예외 |
| 등급을 지정하지 않은 일괄 문 | 정상(DB 기본값) |

- 위치: `app/app/models/grading.py`. ORM 저장 직전 훅이라 **B 서비스뿐 아니라 같은 테이블에 쓰는 모든 코드**에 적용됩니다
- API 입력 스키마는 원래부터 `grade`를 받지 않습니다(B2)
- ORM을 거치지 않는 SQL은 DB 기본값과 CHECK(5등급)까지만 보장됩니다

## 3. 검증

- 전체 테스트 547건 통과
- 테이블별: 생성 시 다른 등급 지정 → 표의 등급으로 저장 / 기존 행 등급 변경 → 거부
- 일괄 UPDATE·INSERT(VALUES, 다중 행 파라미터)에 다른 등급 → 거부, 등급 미지정 일괄 문은 허용
- 변이 검사 3종(자동 부여 제거, 변경 거부 제거, 일괄 문 검사 제거) 모두 테스트가 검출

- A14 말투 프로필(`writing_profiles`, 개인) 등급표 추가 완료(10/23)
