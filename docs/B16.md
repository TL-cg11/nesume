## 7. 10/28 갱신: C11-AUTHZ-05(운영자 mask) 사전 조건 준비

- 배경: AUTHZ-05는 운영자가 일반 사용자 자소서를 AI로 조회할 때 mask를 기대한다. mask는 **검색 결과의 등급 판정**에서 나와야 하는데, 지금 공유 가드레일에 검색기가 없다(A·C 10/28 확인)
- 역할 정리(10/28)
  - C: `PersonalRetriever`(가드레일 규약 그대로) + `PolicyChunk.decision`(역할×등급 판정) — feat/c-authz09-unmiss
  - A: `_shared()`에 `retriever=build_retriever()` 주입 + 청크 판정을 verdict에 merge
  - D: bge-m3 임베딩 서빙(없으면 `build_retriever()`가 None → 검색 생략, 현행과 같음)
  - B: 러너 시더가 사전 조건 `target: user_resume`을 만든다(이번 변경). ENDPOINTS는 그대로(검색은 공유 가드레일에 붙으므로 기존 AI 엔드포인트로 투입해도 검색을 거친다)
- 시더 `target: user_resume`
  - 일반 사용자(시드 user) 소유 자소서 1건(연락처 포함 → 저장 때 토큰화, B7)
  - `DbSeeder(..., embedder=...)`가 있으면 저장본(토큰화된 본문)을 C3 `index_personal`로 개인 인덱스에 적재(source_id=자소서, chunk_index=문항 순서)
  - 임베더가 없으면 인덱싱을 건너뛰고 결과 `checks_unverified`에 `retrieval(임베더 없음)` 표시 → 리포트에서 원인이 보인다
- 감사 로그 `doc_ids`(항목당 64자)에 C 형식 `resume:<uuid>#0`(45자)·`experience:<uuid>#0`(49자) 들어감 확인
- 테스트: 임베더 없을 때 미확인 표시 / 가짜 임베더로 적재 시 연락처 원문 없이 토큰만 인덱스에 있음
- 남은 것: 임베더가 생기면 러너 실행부(`__main__`·측정 테스트)에서 같은 임베더를 시더와 가드레일 양쪽에 넘긴다(색인과 검색이 같은 임베더여야 함)
