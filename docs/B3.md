## 1. 결과 요약

- spec 10.1의 감사 로그 필드 18개와 민감 등급은 B1·B2에서 이미 구현됨
- B3에서는 **값 무결성 제약 3종**과 **90일 보관 정리**를 추가

## 2. 무결성 제약 (DB가 저장을 거부하는 경우)

| 제약 | 거부하는 값 | 이유 |
|---|---|---|
| `doc_grades` 값 | 5등급(public / internal / personal / sensitive / confidential) 외의 값 | 대시보드(D15)·리포트(B22) 집계 오류 방지 |
| `test-` 접두어 ⇔ `is_test` | `session_id`가 `test-`로 시작하는데 `is_test=false`, 또는 반대 | 테스트 트래픽이 운영 지표에 섞이지 않게 (spec 5.5, 10.1) |
| `query_hash` 형식 | SHA-256 소문자 16진수 64자가 아닌 값 (비어 있는 것은 허용) | **질의 원문이 해시 칸에 저장되는 사고 방지** (spec 10.2 "원문 저장 안 함") |

- 제약을 위반하면 그 로그 행은 저장되지 않음 → 기록 함수(B11)에서 저장 전 검증 예정

## 3. 90일 보관 (spec 10.2)

- 90일이 지난 로그를 **오래된 것부터 1회 최대 5,000행** 삭제
- 실행: `python -m app.features.audit.retention`
- 자동 실행(스케줄링)은 다운로드 토큰 정리와 같이 **보류**, 필요 시 수동 실행
- 계정 삭제 시 user_id 익명화는 B20에서 처리

## 4. 다른 팀이 알아야 할 것

**A (작성 AI, A8 가드레일)**
- 감사 로그를 쓸 때 지켜야 할 형식
  - `query_hash`: 원문 `hashlib.sha256(원문.encode()).hexdigest()` (소문자 64자)
  - `doc_grades`: 등급 영문 값만
  - 테스트 요청은 `session_id`를 `test-`로 시작하고 `is_test=true`
- **확인 요청**: `doc_ids`와 `doc_grades`를 **문서별로 짝지어** 같은 길이로 기록하는지? (예: 문서 3개 → 등급 3개) 그렇다면 두 배열 길이 일치 제약을 추가할 예정

**B (평가 러너 B16)**
- 러너의 요청은 `session_id`를 `test-` 접두어로, `is_test=true`

**D (인프라)**
- 감사 로그 정리 배치 자동 실행은 보류 중. 결정되면 CronJob 요청 예정
